# App 端全页面 UI 中重构设计

## 背景

主人希望重构 `medical-mp` 的所有页面，但本轮目标明确聚焦在 **UI 重做**，不是底层业务逻辑或大规模代码架构重写。期望结果是把当前小程序从“功能可用但页面风格零散”的状态，升级为一套统一、专业、可信的医疗产品界面。

本轮已明确：
- 重构类型选择为 **UI 重做**
- 整体风格选择为 **A. 医疗专业感**
- 菜单需要补齐 **icon**
- 重构力度选择为 **中重构**，即允许调整页面结构与信息层级，但不重做整套导航与核心业务流程
- 推进顺序为 **问诊主链路 > 预约 > 我的**，但最终覆盖全部 app 端页面

## 目标

- 将 `medical-mp` 全部页面统一到一套医疗专业感视觉系统下
- 提升页面的品牌一致性、信息层级和产品完成度
- 保留现有主流程和主要功能入口，不做大改版式流程重构
- 为底部菜单（TabBar）补齐风格一致的图标系统
- 统一数字人相关品牌文案与自称方式

## 非目标

- 不改后端接口协议
- 不新增复杂业务能力
- 不做大规模状态管理迁移
- 不把小程序改造成科技感强烈的 AI 产品风格
- 不引入与业务无关的大型设计系统依赖

## 产品与品牌方向

### 视觉气质

采用 **医疗专业感** 方向，核心关键词为：
- 干净
- 克制
- 可信
- 柔和
- 清晰

避免走向：
- 深色科技蓝黑风
- 过度陪伴感的粉色风格
- 过重装饰、强阴影、夸张渐变

### 品牌命名规则

统一使用以下规则：
- **页面品牌位**：`数字人医疗助手`
- **对话内自称**：`我是你的医疗助手安禾`
- **页面空间有限时**：`我是你的医疗助手`

设计意图：
- 页面标题位优先体现产品定位，而非直接拟人化命名
- 在对话中保留“安禾”，强化数字人陪伴感和人格记忆点
- 在小空间里优先保留“医疗助手”身份，避免单独出现“安禾”让新用户理解成本升高

## 重构范围

本轮覆盖以下页面：
- `pages/login/login`
- `pages/chat/chat`
- `pages/doctors/list`
- `pages/doctors/detail`
- `pages/appointment/list`
- `pages/appointment/detail`
- `pages/mine/index`

## 重构策略

采用 **先统一视觉系统，再逐页落地** 的方式，而不是逐页独立重做。

### 推荐执行顺序

1. 登录页
2. 问诊页
3. 医生列表页
4. 医生详情页
5. 预约列表页
6. 预约详情页
7. 我的页
8. TabBar / 导航统一收口

这样做的原因：
- 核心链路优先，用户首先感知的是入口和问诊体验
- 医生页自然承接问诊结果
- 预约与我的页在统一视觉规则后改造成本更低

## 全局视觉系统

### 色彩

建议建立一套统一设计令牌：
- 主色：医疗蓝
- 背景色：浅蓝灰 + 白
- 成功色：柔和绿
- 提醒色：柔和橙
- 风险色：克制红
- 中性色：不同层级的灰蓝文本与边框色

原则：
- 颜色优先服务“信息层级”和“信任感”
- 避免高饱和度大面积使用

### 基础组件风格

统一以下视觉基元：
- 卡片圆角、阴影、描边强度
- 按钮层级：主按钮 / 次按钮 / 幽灵按钮
- 输入框、搜索框、筛选条
- 页面头部标题区
- 空状态、loading、错误状态
- 列表卡片与详情卡片

目标是让页面切换时用户明显感到“这是同一个 app”，而不是一组临时拼接页面。

## 页面级设计

### 一，登录页

#### 目标
让登录页从普通功能页升级为产品入口页，第一眼就传达：
- 这是医疗助手类产品
- 品牌可信、专业、克制
- 用户登录后将进入数字人问诊体系

#### 页面结构
1. **品牌头区**
   - 品牌位：`数字人医疗助手`
   - 副标题：简短说明，如“智能问诊与预约服务”
   - 位置偏页面上半区，拉开呼吸感

2. **品牌插图区 / 形象引导区**
   - 可使用静态品牌卡或柔和医疗图形背景
   - 不要求在登录页直接加载完整 Live2D
   - 目标是建立产品气质，而不是展示技术能力

3. **登录表单卡片**
   - 白底卡片承载账号与密码输入
   - 输入框尺寸、圆角和间距统一移动端产品风格
   - 登录按钮作为主按钮处理

4. **辅助说明区**
   - 保留简洁提示，不堆砌说明文案

#### 关键要求
- 删除默认自动填充的账号密码
- 视觉上更像产品入口而不是开发测试页

### 二，问诊页

#### 目标
将问诊页打造为 app 的主场景，突出“数字人医疗助手”与“问诊交互”两个核心。

#### 页面结构
1. **顶部品牌区**
   - 品牌位：`数字人医疗助手`
   - 辅助状态：如“在线问诊中”“正在为你服务”
   - 文案克制，不强调技术名词

2. **数字人主视觉区**
   - 数字人是页面核心视觉中心
   - 背景更整洁、柔和，减少演示页感
   - 保留“数字人出来前全屏 loading”的首屏策略

3. **对话工作区**
   - 消息区
   - 输入区
   - 轻量快捷入口，如重新开始问诊、查看推荐医生、查看预约
   - 仍以“问诊”作为单一主任务，不让页面杂乱

#### 关键要求
- 数字人区与聊天区在视觉上形成统一界面，而非上下割裂的两个模块
- 欢迎语和空状态里使用“我是你的医疗助手安禾”
- 输入区要更像医疗咨询入口，而不是普通 IM 聊天框

### 三，医生列表页

#### 目标
让医生列表成为问诊后的自然下一步，帮助用户快速理解推荐依据并做选择。

#### 页面结构
1. **顶部说明区**
   - 标题如“推荐医生”或“为你推荐的医生”
   - 说明推荐来源，例如基于症状分析

2. **搜索与轻筛选区**
   - 搜索医生 / 科室
   - 筛选项控制在必要范围：科室、职称、排序方式

3. **医生卡片列表**
   - 姓名
   - 职称
   - 科室
   - 擅长方向
   - 可预约状态
   - CTA 明确：查看详情 / 去预约

4. **空状态**
   - 提供下一步引导，而不是单纯无数据提示

#### 关键要求
- 强化推荐语境，弱化普通列表页感
- 若能轻量展示“推荐理由”，优先纳入设计

### 四，医生详情页

#### 目标
帮助用户快速判断当前医生是否适合自己，并顺畅进入预约决策。

#### 页面结构
1. **医生头卡**
   - 头像 / 占位图
   - 姓名、职称、科室
   - 是否可预约

2. **擅长与简介区**
   - 擅长方向优先
   - 简介次之
   - 控制信息堆叠密度

3. **出诊 / 可预约信息区**
   - 让用户尽快知道能否预约、最近何时可约

4. **决策操作区**
   - 主按钮：立即预约
   - 次按钮：返回继续看其他医生
   - 可预留“继续问安禾”类回流入口

5. **辅助信任信息区**
   - 用于增强决策信心，而不是堆字段

#### 关键要求
- 页面定位为“预约决策页”，不是档案资料页
- 主按钮明显且位置稳定

### 五，预约列表页

#### 目标
让预约列表从简单记录页升级为可管理的预约中心。

#### 页面结构
1. **标题区**
   - 标题：`我的预约`
   - 辅助文案：查看和管理预约

2. **状态筛选区**
   - 全部 / 待就诊 / 已完成 / 已取消
   - 使用轻量标签切换

3. **预约卡片列表**
   - 医生姓名
   - 科室 / 职称
   - 时间
   - 状态
   - 对应 CTA

4. **空状态**
   - 引导用户去问诊或找医生

#### 关键要求
- 突出最近要处理的预约
- 状态色与全局系统一致

### 六，预约详情页

#### 目标
让用户快速确认预约状态、关键信息以及下一步操作。

#### 页面结构
1. **状态头卡**
   - 待就诊 / 已完成 / 已取消

2. **核心信息区**
   - 医生
   - 科室
   - 时间
   - 时段
   - 编号（如有）

3. **就诊说明区**
   - 到院提醒、准备事项、注意事项

4. **操作区**
   - 根据状态展示不同主按钮
   - 次按钮可回流到问诊或重新预约

5. **关联引导区**
   - 连接其他页面，不让详情页成为死页面

#### 关键要求
- 页面像“服务确认单”，而不是数据库详情页
- 状态和下一步操作最优先

### 七，我的页

#### 目标
让“我的”成为个人服务入口，而非杂项堆叠页。

#### 页面结构
1. **个人头部卡**
   - 用户信息
   - 简短服务型说明

2. **快捷入口区**
   - 我的预约
   - 问诊记录 / 继续问诊
   - 找医生

3. **服务设置区**
   - 必要的账号或退出操作
   - 控制复杂度

4. **安禾入口区**
   - 用一张引导卡将用户带回主链路

#### 关键要求
- 整体更像“个人服务台”
- 加强回流主流程能力

## TabBar 与菜单 icon

### 目标
把底部导航从裸文字 tab 升级成完整产品导航。

### 保留结构
- 问诊
- 预约
- 我的

### icon 方向
采用统一线性医疗风 icon，要求：
- 简洁
- 线条统一
- 与医疗专业感一致
- 不使用夸张渐变或重拟物图标

建议图标语义：
- 问诊：对话 / 医疗助手语义
- 预约：日历 / 时钟语义
- 我的：用户 / 个人中心语义

### 关键要求
- 选中态与未选中态清晰
- 与页面视觉系统一致，避免 TabBar 仍像默认系统组件

## 文案与交互语气

整体交互文案风格应为：
- 专业，但不冰冷
- 简洁，但不机械
- 服务感明确，但不过度拟人化

应用方式：
- 页面上强调“医疗助手”身份
- 对话里通过“安禾”建立熟悉感
- 错误、空状态、loading 等提示避免技术腔

## 风险与边界

- 本轮属于中重构，允许改布局和信息层级，但不建议同步做业务流程大换血
- 若多个页面都各自发挥，很容易失去整体性，因此必须先定义全局视觉系统再落页
- TabBar icon 若采用图片资源，需要同步考虑小程序资源管理；若采用图标字体或本地图标集，要优先选择后续维护成本低的方案

## 验收标准

- 所有页面视觉风格统一，明显属于同一产品
- 核心链路页面具备更强的医疗产品感，而不是工具页感
- 数字人品牌文案规则统一落地
- TabBar 具备完整 icon 和选中态
- 问诊、医生、预约、我的四条体验线在视觉和信息层级上都得到提升
