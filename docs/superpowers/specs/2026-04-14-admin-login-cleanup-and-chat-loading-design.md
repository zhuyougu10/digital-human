# Admin 登录默认值清理与聊天页首屏 Loading 设计

## 背景

主人提出两个前端体验问题：

1. 管理端登录页当前会默认自动填写账号密码 `admin / admin123`，需要删除这组默认值。
2. 小程序聊天页在数字人尚未加载完成前，会直接露出页面主体。需要增加全屏 loading，等数字人先出来，再进入页面；但不要让会话初始化或历史消息的慢请求把整页长期卡死。

本次需求都属于前端改动，不涉及后端接口契约变更。

## 目标

- 管理端登录页首屏时，用户名和密码输入框为空。
- 小程序聊天页首次进入时显示全屏 loading。
- 当 Live2D 首次成功加载完成后，隐藏全屏 loading 并显示页面主体。
- 如果会话初始化或历史消息较慢，允许页面先展示，保留现有局部加载行为。
- 如果 Live2D 加载失败或超时，不能永久停留在全屏 loading。

## 非目标

- 不改管理端登录接口、鉴权逻辑、记住密码逻辑。
- 不新增账号记忆/自动填充策略。
- 不重构聊天页整体架构。
- 不新增复杂动画、品牌开屏页或骨架屏系统。

## 方案对比

### 方案 A，最小改动，推荐
- 删除管理端登录页的默认表单值。
- 在聊天页增加一个全屏 loading 蒙层。
- 蒙层默认显示，Live2D 首次 ready 后隐藏。
- 会话初始化、历史消息保持现状，慢时只影响局部内容。
- 如果 Live2D 失败或超时，主动关闭全屏 loading，并提示用户数字人加载失败。

优点：改动小、风险低、最符合主人选择的“折中方案”。
缺点：若模型先好、历史消息未好，用户会先看到页面框架和局部空态。

### 方案 B，强一致首屏
- 全屏 loading 需等待模型与会话初始化全部完成。

优点：首屏更整齐。
缺点：任一链路变慢都会让整页长时间黑屏等待，不符合本次偏体验优化的目的。

### 方案 C，增强版过渡动画
- 先用品牌 loading，再在模型 ready 后淡出。

优点：观感更好。
缺点：本轮需求不需要，额外样式和状态复杂度偏高。

## 最终设计

采用方案 A。

### 一，管理端登录页
修改 `medical-admin/src/views/login/index.vue`：
- 将 `loginForm.username` 初始值从 `admin` 改为空字符串。
- 将 `loginForm.password` 初始值从 `admin123` 改为空字符串。
- 保持原有校验逻辑不变，仍要求用户名和密码非空后才允许提交。

预期结果：
- 打开登录页时不再自动填入默认账号密码。
- 登录交互和接口调用行为保持不变。

### 二，小程序聊天页首屏 Loading
修改 `medical-mp/src/pages/chat/chat.vue`：
- 新增首屏状态：
  - `isPageBootLoading`，控制全屏 loading 是否显示
  - `live2dLoadTimedOut`，标记是否走到超时兜底
- 首次进入页面时默认显示全屏 loading。
- 在 `renderer.loadModel(...).then(...)` 成功回调内，将 `isPageBootLoading` 置为 `false`。
- 若 `loadModel` 失败，则关闭全屏 loading，并给出 toast 或状态提示。
- 增加超时兜底，例如 8 到 12 秒区间内若仍未 ready，则自动隐藏全屏 loading，避免页面永久卡死。

### 三，聊天页展示策略
- 全屏 loading 只绑定 Live2D 首次加载状态，不依赖会话初始化或历史消息加载完成。
- 页面主体可始终存在于 DOM/视图树中，但在 loading 蒙层显示时被覆盖。
- 历史消息仍沿用当前顶部“加载中...”等局部提示。

这样可以保证：
- 主人要求的“数字人没出来前全屏等待”被满足。
- 同时不会让聊天接口慢、历史慢时把整个页面长时间卡住。

### 四，异常与兜底
- Live2D 加载失败：
  - 关闭全屏 loading
  - 输出现有错误日志
  - 给用户一个轻提示，如“数字人加载失败，请稍后重试”
- Live2D 加载超时：
  - 自动关闭全屏 loading
  - 保留页面可用性
  - 可在状态条里维持普通服务文案，不额外阻塞聊天

## 测试与验收

### 管理端
- 打开登录页，用户名为空。
- 打开登录页，密码为空。
- 手动输入账号密码后仍可正常登录。

### 小程序聊天页
- 首次进入聊天页时先显示全屏 loading。
- Live2D 成功加载后，全屏 loading 消失。
- 若会话初始化较慢，页面可以在 loading 消失后继续加载消息，不会整页卡死。
- 若 Live2D 加载失败或超时，loading 也会退出，不会永久停留。

## 风险

- `chat.vue` 当前同时承担模型初始化、聊天状态、TTS、历史消息等职责，新增状态时要避免和现有 `isThinking`、`isLoadingHistory` 混淆。
- 如果 loading 蒙层 z-index 或布局不当，可能遮住后续交互或与安全区冲突。
- 若模型在失败后重试策略不清晰，可能出现 loading 已消失但状态提示仍与真实加载状态不一致；本轮不引入自动重试，只保证不锁死页面。
